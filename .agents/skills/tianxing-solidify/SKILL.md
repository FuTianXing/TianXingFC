# tianxing-solidify 固化进理论总纲

工作区：天行新学（`D:\software\TianXingFC`）。基准在 `理论总纲/`，未确认内容先住 `内部草稿/`。流程六步：授权确认 → 收料定级 → 选落点 → 同步涟漪 → 落笔 → 检查与报告。

三条不变量：**授权在先**（`理论总纲/` 未经作者明示不得修改，"我觉得可以固化"不构成授权）；**一期一入**（同一批固化写进同一条修订记录，标注触发与来源）；**不升格**（作者裁决、可复现数值、待攻项各按自己的层级措辞，固化的只是位置）。

## 0. 授权与预检

1. 触发词：固化、固化进理论总纲、写进基准、把这批结论落到总纲、更新基准文档。触发后再动手；仅"讨论结论"不得动基准。
2. `git status --short` 先看基准文件是否被并行会话在途修改。在途时在报告中声明，锚点最小化，绝不整体重排。
3. `rg -n '^#{1,4} ' <文件>` 重读结构：标题层级、编号规律与待攻清单位置可能已被改写过。

## 1. 收料与严格程度定级

1. 列清单：每条待固化结论 + 来源层级。优先级序为作者裁决 > 定稿论文 > 验证脚本判据（可复现数值事实）> 内部草稿分析 > 他会话产物。
2. 按体系四级声明制归级（定理级、条件性命题级、纲领、直觉），并让固化文字的动词与级相配：判定、验证、裁决、待攻、拟议。
3. 摘出可追溯三件套：脚本路径、验证注记名、判据编号。固化文字必须能一条链追回来源，否则不写。
4. 未闭合项一并带上（写明"待攻项为…"）。固化位置不等于结案。

## 2. 落点分工（七类基准文件各自的职责）

| 文件 | 装什么 | 注意 |
|---|---|---|
| `元相子理论的时空观` | 机制正文 | 新增机制段落进对应节，待攻清单加一项，§十边界与未闭合处加一句，头部修订记录加一条 |
| `天行新学核心洞见速览` | 一句话洞见条目 | 只在相关条目的句尾追加从句，不新开条、不新开段 |
| `子理论索引` | 论文转正条目：主行（题名加状态徽标加日期）加一句提要（不超 60 字），插入对应分组节；状态跟踪区只收尚未入分组清单的论文；评审与登记细节随论文正稿修订记录走，旧 `论文状态跟踪详录` 已废弃归档（根目录 `归档/`），不再引用与追加 | 节头篇数计数是显式数字（如"7 篇"），增删条目必须改数 |
| `术语表` | 新术语或术语语义更新 | 引力与运动机制落第十节；节标题补增补日期 |
| `元相子理论的实验可检验预言清单` | 可证伪条目 | §8 自写"只编目已有论文中已写明的预言，不新增断言"：来源非论文者须加透明度声明并把强度评级标为拟议 |
| `元相子理论已解决难题总览` | 只有已解决才进 | 未闭合项不进，走开放问题总览 |
| 下游汇总（`要点总览`、`下一步攻坚路线图`、`革命性的全面论证`、`综合评价`） | 不装新内容 | 只同步计数与名称列表 |

## 3. 计数与交叉引用涟漪（最易漏的一步）

1. 总数一变，先全工作区扫描：`rg -n "<旧数> 项" --glob "*.md" -g "!_tools/**" -g "!外部理论参考/**"`，列全引用点。
2. 逐个同步，名称列表一起改：A 级条目常在正文里被逐一列名，只改数字会留下矛盾。
3. 同步后 `rg` 复查零残留。`外部理论参考/` 按规范不动。
4. `内部草稿/` 里的历史陈述（"当时为零条目"）仍为真，不追改成新数，加"（日期已补齐）"标注即可。

## 4. 落笔纪律

2. 正文段落 ≤300 字符，含标点与 LaTeX 源码。拆段只插分隔符，用 `re.sub(r'\s+','',before) == re.sub(r'\s+','',after)` 证明零遗漏。
3. 内链写 `[[文件名]]`；新写的引用不写书名号（既有 `《》` 按规范不强制迁移，批量转换交 `wikilink-batch`）。
4. 修订记录用分级列表：`  - **日期 事件名**（触发或依据）` 加缩进要点；同日多事件各占一条。
5. 同一事实只在一处展开，其余处引用。四处重复同一段会让后续同步变成四处维护。

## 5. 落盘与检查

1. 多处替换走 Python 脚本（写 `_tools/`，任务收尾删除）；含中文禁止 bash 内联 `-c`；锚点取无标点子串，`assert text.count(old) == 期望次数` 后才落盘。
2. **反斜杠陷阱**：Python 普通字符串里的 `\t`、`\v`、`\n`、`\b`、`\f` 会被解释成控制字符，把 LaTeX 命令写成乱码（`$\theta$` 变 TAB + heta）。含 LaTeX 的批量替换一律 r-string 或双反斜杠，落盘后必查控制字符。
3. 落盘后跑统一检查：

```
python "C:\Users\Administrator\.agents\skills\tianxing-solidify\scripts\solidify_check.py" <文件>... [--root D:\software\TianXingFC]
```

硬伤（退出码 1）：控制字符、wikilink 未解析。提示（不影响退出码）：超长段落、序列词套话、残余书名号。

4. 死链与条目覆盖另配 `wikilink-batch` 的 `scripts/link_audit.py`。

## 6. 报告

1. 逐文件说明改了什么、每条结论进了哪一层、哪些属待作者确认（强度评级、规则放宽、边界判断），并给出可回退提示。
2. 计数涟漪涉及的下游文件必须点名，不能只报"已同步"。
3. 末尾一句话报本轮提交情况（已提交 N 个文件；未获作者明示推送时注明"未推送"）。**提交自动，推送人工**：每完成一个实质工作单元即自动 `git add` + `git commit`，无需等待作者指示；提交粒度按主题，同一篇文档的多次编辑合并为一次提交；`git push origin master` 仅在作者明示"推送"时执行。

## 特例速查

| 情形 | 处理 |
|---|---|
| 基准文件正被并行会话修改 | 报告中声明；最小锚点编辑，不整体重排，不改他人条目 |
| 结论只到内部草稿层级，作者要求固化 | 保留"待攻/拟议"标注，不升格为定案 |
| 预言清单 §8 与新增条目来源层级冲突 | 加透明度声明，评级标"拟议"，报告请裁决是否放宽该条 |
| 总数变化 | rg 全工作区扫引用点，逐个同步（含名称列表），复查残留 |
| 内部草稿里的历史陈述 | 不追改，加"（日期已补齐）" |
| 固化对象横跨多份基准 | 按职责分工表分发，一处展开、其余引用 |
| 术语既有措辞与新结论冲突 | 改术语表词条并标日期，正文同步 |
| 作者只给一句"固化" | 按本技能默认落点全跑，报告里把所有待确认项列出来 |
| 结论涉及废除旧方案 | 旧文不删，加"文档状态说明"并注明替代者 |
