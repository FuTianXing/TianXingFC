# 论文修改技能

你根据一份评审报告对论文进行系统性修改。修改按评审问题的严重程度（A级/B级/C级）逐级处理，每完成一级做一次验证，确保不引入新问题。

修改时**不得改变原文的核心论纲和学术立场**，只修复评审指出的问题。

---

## 修改流程

### 第一步：阅读评审报告

通读评审报告，确认：
- 哪些问题是A级（必须改）？
- 哪些问题是B级（建议改）？
- 哪些问题是C级（可选项）？
- 作者是否明确要求了处理范围？

### 第二步：规划修改顺序

按"先大后小、先结构后细节"的原则排序：

1. 结构性问题（缺引言/结论、章节顺序错乱）
2. 逻辑问题（矛盾、跳跃、定义不精确）
3. 引用问题（缺文内引用、参考文献格式）
4. 格式问题（LaTeX错误）
5. 语言问题（术语一致性、语病、标点）

### 第三步：逐级修改

#### A级问题处理

每处理一个A级问题，**必须**：
1. 在修改后立即用 `read_file` 验证改后的上下文，确认替换位置正确，没有破坏周围内容
2. 记录修改了什么、改在哪里

#### B级问题处理

每个B级问题视情况处理：
- 涉及文字修改的：直接用 `edit_file` 或 `multi_edit`
- 涉及结构补充的：在最近的自然断点处插入新段落
- 涉及强主张弱化的：保留核心意思，添加限定词或条件说明

#### C级问题处理

C级问题在完成A/B级后统一处理：
- 可批量处理的（如全文字符替换）：使用 `_tools/replace_punct.py`
- 需要逐处改的：用 `edit_file`

### 第3.5步（可选）：去除AI味道

如果作者要求或评审指出"AI味道过重"，在完成A/B级问题后、C级问题之前，专门执行一轮AI味道清洗。

#### AI味道的典型特征与处理

**1. 序列词滥用**

| AI味写法 | 去除后 |
|----------|--------|
| "首先，……其次，……最后，……" | 打破序列，改用自然衔接（如"一是……二是……"或直接递进） |
| "第一，……第二，……第三，……" | 仅保留到第二层，第三点融入前文或用"此外"过渡 |
| "主要有以下三个方面" | 直接陈述，不预先宣告 |

**2. 套话空话**

| AI味写法 | 去除后 |
|----------|--------|
| "值得注意的是，" | 直接陈述事实本身 |
| "需要指出的是，" | 同上 |
| "众所周知，" | 删除或改为具体背景 |
| "不可否认的是，" | 删除 |
| "从某种意义上说，" | 删除或具体化 |
| "在某种程度上，" | 删除或量化 |
| "显而易见，" | 直接陈述 |
| "毋庸置疑，" | 删除 |

**3. 过度强调词**

逐处检查以下词汇，删除或替换一半以上：
- "深刻" → 删或具体化（"深刻影响" → "重塑"）
- "重要" → 保留1/3，其余删或替换为"关键""核心"等有实际含义的词
- "关键" → 只在真正关键处使用
- "根本" → 只在真正根本处使用
- "极其" → 删
- "十分" → 删
- "非常" → 保留1/5

**4. 过度规整的段首句式**

扫描全文段首句：
- 如果连续3段以上以同一句式开头（如全是"XX是……""XX的……"），打乱节奏
- 将部分段首改为直接设问、引语、数据或短句

**5. 连接词堆砌**

| 过度使用 | 处理方式 |
|----------|---------|
| "然而" | 保留1/3，其余改为"但""不过"或直接不用 |
| "因此" | 保留1/3，其余改为"所以""故"或因果关系隐含在句式中 |
| "从而" | 保留1/3，其余删除或改为"因而" |
| "由此可见" | 删 |
| "基于此" | 改为"由此"或删 |
| "换言之" | 保留1/2 |

**6. 句式高度一致**

如果连续段落都是"主题句 + 展开句 + 总结句"的三句结构，打破之：
- 部分段落只用一句收束
- 部分段落以反问结尾
- 部分段落插入括号补语或破折号插入语（仅限短插入）
- 部分段落用短句收尾（3-5字）

**7. 个性化缺失**

一篇有思想深度的论文应当有作者的"声音"：
- 检查是否有独到的比喻、出人意料的类比；如有，保留并突出
- 检查句式是否过于"顺畅"：偶尔的断句、让步、插入语反而更接近人的写作
- 检查是否存在作者个人的学术判断句式（"本文更倾向于……"而非"研究表明……"）

#### 执行原则

- **不删内容，只改表达**：AI味道的去除是改变"怎么说"，不改变"说什么"
- **保持学术性，去掉模板感**：目标是让论文读起来像"一个活人写的"，而非"一个模板填的"
- **保留原文的风格偏好**：如果原文故意使用了某种排比或文武句，不要强行打破

#### 验证

清洗完成后，随机抽3-5段读一遍：
- 读起来像人写的吗？
- 有没有觉得"太顺了，不对"的地方？
- 有没有仍然残留的"首先"/"值得注意的是"？

### 第四步：写后验证

每完成一个级别的全部修改，**用一条 Python 命令做机器自查**，而非逐项人工核对。人工核对会漏（历史事故：首轮审读漏判两处超 300 字符段落，第二轮才发现）。

| 检查项 | 判据 | 说明 |
| --- | --- | --- |
| 超长段落 | 正文段落 > 300 字符为 0 | 例外：对照表、数据清单、代码块、引用块、列表项（含有序列表 `N. `） |
| 控制字符 | 计数为 0 | 排除 `\n\r\t` |
| 美元符配对 | `$` 计数为偶 | LaTeX 定界符成对 |
| 行尾符 | 与原文一致 | 混合行尾（CRLF 与 LF 并存）须先统一 |
| 内链目标 | 未命中为 0 | 批量提取 `[[...]]` 目标，比对全库文件名 |
| 交叉引用 | 条号与章节号仍有效 | 见「交叉引用核验」 |

**一次性自查脚本**（复检与主修改写进同一条命令，一次成型）：

```python
import io, re, os, glob
P = r'<目标文件绝对路径>'
s = io.open(P, encoding='utf-8', newline='').read()
L = s.split('\n')
print('lines', len(L), '| crlf', s.count('\r\n'))
for pat in ['首先', '其次', '最后',
            '值得注意', '众所周知', '深刻', '极其']:
    n = s.count(pat)
    if n: print('  命中', pat, n)
bad = [(i + 1, len(x)) for i, x in enumerate(L)
       if len(x) > 300 and not x.startswith('|')
       and not re.match(r'^(  )*- ', x) and not re.match(r'^\d+\. ', x)]
print('超长段:', bad)
print('ctrl', len([c for c in s if ord(c) < 32 and c not in '\n\r\t']),
      '| $偶', s.count('$') % 2 == 0)
tgt = set(re.findall(r'\[\[([^\]\|]+)', s))
allmd = {os.path.splitext(os.path.basename(p))[0] for p in glob.glob('**/*.md', recursive=True)}
print('链接', len(tgt), '未命中:', [t for t in tgt if t.split('/')[-1] not in allmd])
```

命中项须逐处看上下文再判断：术语引述、实际文件名、独立否定句都属合法保留。

另有两项机器查不出的，须人工过一遍：

- 修改后的句子是否通顺、有无语法断裂；
- 有无意外删除或覆盖原文内容（长文档重写时末尾段落最易丢；稳妥做法是只改目标处，用短锚点做靶向替换）。

## 重要技术约束

### 文件大小限制

`write_file` 在内容超过约 30KB 时会因 JSON 载荷截断而失败（`unexpected end of JSON input`）。如果论文较大：

**方案一（推荐）**：拆为上/下两篇分别写入，然后用 shell 拼接：

```powershell
Get-Content 上篇.md | Set-Content 目标.md
Get-Content 下篇.md | Add-Content 目标.md
Remove-Item 上篇.md, 下篇.md
```

**方案二**：使用 `_tools/write_large_file.py`（如果已存在）：

```powershell
Get-Content 源内容.txt -Raw | python _tools/write_large_file.py 目标文件.md
```

### 分段修改优于重写

除非原文问题极为严重，否则优先用 `edit_file` 和 `multi_edit` 做靶向修改，而非重写整个文件。分段修改可以逐段验证，风险更低。

### 内容定位优先于行号索引

修改一律用**唯一子串锚点**定位，不用行号。行号在「先替换后插入」的流程中会因字符串长度变化而整体位移，极易插错位（历史事故：同一文档连续三次插错，出现编号重复、新节落在旧节之前、新章跑到章外）。

锚点须带断言，命中数不为预期时立即报错：

```python
def rep(a, b, cnt=1):
    global s
    n = s.count(a)
    assert n == cnt, 'ANCHOR %r hits=%d expect=%d' % (a[:60], n, cnt)
    s = s.replace(a, b, cnt)
```

插入落在标题之前时用 `L.insert(k, block)`（k 取锚点下标），新块与后继标题之间显式补空行。锚点匹配失败时用 Python 打印实际字符核对，不要凭字形猜（Unicode 弯引号、em-dash、CRLF 是高频陷阱）。

### 反向重编号

插入新节导致后续节号顺延时，**从后往前**执行改名（九→十、八→九、七→八、六→七、五→六）。正向改名会与尚未改名的旧节号撞车。

### 交叉引用核验

文档内的条号、章节号、清单序号在修改后可能陈旧，须逐条打开被引文档确认。历史事故：某注记头部记「速览第 8 条」，而该条实为另一主题（最大熵态推论），定域与非定域落在第 9 条，系条目插入导致的位移，陈留多日未觉。

### 修改前备份与临时脚本清理

大改动前先 `cp` 一份到 `_tools/`；收尾时删除备份与临时脚本（修改替换类脚本用完即删）。已入库文件删除后仍可从 git 历史找回；未跟踪文件删除前先确认可丢弃。

### 落盘后复检长公式的定界符

含独立公式的文档用 `write_file` 整体落盘时，`$$` 定界符偶有退化（两处 `$$` 变单 `$`）。落盘后按 `^\$\$` 复检块数。含 LaTeX 的替换用 r-string，落盘后查控制字符（普通字符串里的 `\t`/`\v`/`\n`/`\b` 会被解释成控制字符）。
