# 验证脚本写作（Verification Script）

**细则正本**：本技能目录下的 `验证规范.md`（`D:/software/TianXingFC/.agents/skills/verification-script/验证规范.md`，随 git 跟踪；2026-10-24 自 `验证脚本/` 迁入）。本技能是操作路由：何时做什么、顺序如何、每条纪律的一句话形态；细则、案例与判据数值一律以正本为准，不一致时以正本为准。历史版本快照在 `D:/software/TianXingFC/_tools/verification-script_SKILL.md.bak-20261021`。

本技能源自 2026-09-29 第 489 至 501 轮实战：十三轮验证中同型错误出现五次，沉淀为可复用的写作纪律，此后随各轮教训增补（2026-10-24 现行八条）。

## 一 核心顺序

判据 → 理论期望 → 判据容差 → 实现 → 冒烟 → 判据循环 → 伪影分层 → 出图 → 注记 → 登记。任何一步倒过来做，产物就不可信。**判据必须先于实现写下来**，每条判据写明「内容 + 期望值 + 判定标准」，期望值要能被实现推翻。

## 二 开工前三条

1. **占号**：先在 `验证脚本/README.md` 末尾追加占位行 `- **<下一个可用号>.** 占位：<本线名> 施工中` 并提交，占号一律走 `.githooks/claim_number.py`（串行化取号）；撞号按 `AGENTS.md` 的「README 编号占位规范」处理（2026-10-24 裁定字母后缀制，不顺延、不改号）。
2. **收料**：列清单——判据编号与原文、理论期望、模型设定、输入常量及其出处（定稿值还是模型单位）、与既有注记的口径关系（新增、修订、还是复现）。判据从登记在案的开放问题、裁决请求的裁定项、上轮遗留的缺口来。
3. **定位既有材料**：同类验证先查 `验证脚本/README.md` 与既有注记，避免重复劳动；480 条之前的 `内部草稿/注记-*.md` 里散落大量「判据草案」，开工前值得搜一遍。

## 三 硬纪律八条（细则与案例见正本对应节）

1. **容差从误差预算推导，差额归因前先做收敛检验**（正本 §四）：容差来自解析截断与数值方法误差两类，禁止未经预算直接设数；出现差额先加密网格看收敛阶，不收敛即协议伪影；归因时每个候选成因单独做成可开关的开关逐个排除。
2. **新配置必跑冒烟检查**（正本 §四）：矩阵维度（Kronecker 每层补单位阵）、Hermitian 性、基矢正交性、随机位形上力非零而基态上力为零，非零且合理再进判据循环。
3. **判据设计三纪律**（正本 §五）：对象类型前置（算符、参数、构型判据、状态描述、统称五类，类型错即问了不存在的对象）、恒真检验（改掉它就 FAIL，构造恒真的 PASS 不含物理信息）、多档扫描（单档超阈不构成信号）。
4. **判据量的协议稳定性审计**（正本 §五.4）：同一档换两三组采样协议看判据量散布，超容差的档只作退出登记；先问判据量在什么条件下稳定，再问它给出什么值；拟合量的基函数共线是协议敏感的主因，显著性低于 3 倍标准误不构成证据。
5. **简并子空间读数前过 EP 四段检验**（正本 §六）：EP1 投影合法性、EP2 提取正确性、EP3 污染量化（取随机组合矢期望值的极差，取本征基列恒为零属平凡检验）、EP4 守恒标签自检，任一段判否即停止读数。可复用 `验证脚本/检验器/extraction_protocol.py`，单算符场景用本技能精简版 `scripts/extraction_checker.py`（`check_extraction(O, H, B)`，含 EP1 至 EP4）。
6. **跨轮移植结论前核对前提的守恒关系**（正本 §八）：守恒关系变则结论失效，判据与前提矛盾时是判据写错。
7. **实现层前置检查三类断言**（正本 §四）：符号约定（数值量与解析量反号逐点吻合即判否）、反解公式（二者成非常数 1 的常数倍即判否）、有限维截断（末两档比值对期望收敛阶）。可复用 `验证脚本/检验器/impl_precheck.py`。
8. **构型自检断言四防线**（正本 §四）：构造双向对表（断言须在已知写错的对照构型上实测不通过）、变换不变量冒烟（须在离壳对照上实测被破坏）、声明与实现单源（公式只在一处，docstring 不写副本）、收尾比对入注记过程记录。可复用本技能精简版 `scripts/construction_checker.py`（`check_construction` 双向对表、`check_invariant` 不变量冒烟含恒真对照）；绑定具体构型的示范见第 809 号脚本 `p809_contraction_corrected.py` 的 `construction_selfcheck`。

另：**协议伪影与物理结论分层报告**（正本 §三）——采样、截断、有限档枚举等构造选择与物理结论分开写，定性升级须写明依据。

## 四 谱类判据的三个坑（正本 §七）

简并度按算符完整自由度计（8 分量每模式 $\pm E$ 各 4 重，漏乘报尺寸不匹配）；能量级读取带符号口径（$E=0$ 附近无态，$\arg\min|E|$ 会先命中负支）；排序谱与模式网格的对应须显式恢复，或改用解析谱按模式算。

## 五 注记与收尾（细则见正本 §十、§十一）

- **注记六件套**：元数据（日期到秒、脚本、判据与通过数、可逆性等级、关联、图）、要判什么、模型设定与判据表（数值照抄脚本输出不凭印象）、图（出图必嵌，图注按绘图面板核对）、严格程度与边界声明（严格层、物理对应假设层、纲领层三层）、过程记录（教训逐条入档，下轮的资产）。
- **可逆性等级必标**：判据敏感（换实现、换口径或换档位会翻）或判据稳健（不翻）。
- **收尾登记**：README 占位改正式行（五要素、行长 ≤300、钩子 `check_readme_entry_format.py` 校验）→ 开放问题登记（**先档案页后总览卡**：判据详情入档案页，总览卡只做状态行替换加至多一行动态，钩子 `check_overview_cards.py` 查体量与日期块）→ 口径变更在注记修订记录与口径消解账各留一行 → 补判据后回改全部登记处的判据数（README、总览卡、档案页至少三处）→ 通俗注记同批出（`内部草稿/`，五段式，尾节声明数值与结论以正式注记为准）。
- **绘图字体**：绘图标签含中文须在 `import matplotlib.pyplot as plt` 后立即设 `Microsoft YaHei` 或 `SimHei`，样板见 `D:/software/TianXingFC/验证脚本/绘图模板.md`；修正既有脚本属纯渲染层处理，不动判据与数值。
- **提交**：按 `AGENTS.md` 的「git 规范」执行（提交一律带 pathspec，不读共享暂存区；显式路径 add）。

## 六 可迁移的通用判据技巧（正本 §十二）

「不存在」类结论须穷举支撑（如 Clifford 单项式全枚举，与数值容差无关）；解析恒等式是最强判据，数值只做确认；维度诊断用三重对照做构造性否定；零读数先穷举排除成因再定因；判否不等于判负（判据设计失效是第三种结论，须区分登记）。
