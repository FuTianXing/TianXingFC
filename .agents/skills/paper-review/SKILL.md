# 论文评审与修改技能（paper-review）

评审与修改是同一闭环的两半：**评审产出独立的分级报告**（不修改原文），**修改按报告逐级落实**（不改变原文的核心论纲和学术立场）。两者共用机器预检与写后验证。附属文件按需读：`references/去AI味指南.md`、`references/修改技术约束.md`（锚点断言、写后自查脚本、反向重编号等技术纪律）。

**快速通道**：已有评审报告、只需修改 → 直接进第二部分；只评审不修改 → 第一部分到输出报告为止。

---

## 第一部分 评审

对一篇学术论文进行系统性评审，按七个维度逐一检查，每个维度输出具体问题清单（按严重程度分级），最后给出总体评价。

### 第零步：机器预检

先跑脚本，把机器可判的问题一次性收齐，避免它们混在人工评审的输出里稀释了真正的 A/B 级问题。

```bash
python .agents/skills/paper-review/scripts/check_discipline.py <论文绝对路径> --root <工作区根目录>
```

退出码 0 表示通过，1 表示有命中（按 A/B/C/D 四组分类，附行号与原文片段），2 表示用法错误或文件不存在。加 `--root` 才启用死链检查；`--limit N` 可改段落字符上限（默认 300）。

| 组 | 覆盖内容 |
|---|---|
| A 语言纪律 | 序列词、套话、强调词 |
| B 转义安全 | 控制字符、U+FFFD 损坏字符、Unicode 数学符号、转义七判据、`\vert` 紧邻字母、LaTeX 命令残部、行内 `$` 奇偶 |
| C 格式结构 | 表格列数不一致、段落超长、一级节号不连续、缺摘要/关键词/参考文献 |
| D 内部链接 | wikilink 死链（需 `--root`） |

**脚本的判定边界**：它只判形式，不判论证。维度二、六、七（内容质量、内部自洽、数学正确性）全部仍须人工评审。脚本报告的每一处仍需定级——通常 C 组归 C 级、B 组中的转义崩溃归 B 级。预检通过不等于论文合格，只说明形式层干净。

### 第一步：全局概览

读一遍全文，建立整体印象：核心论纲是什么、是否清晰？论证的逻辑链条是否完整？目标读者是谁，语言和深度是否匹配？

### 第二步：逐维度审查

**维度一：结构完整性**。标题是否准确反映内容；摘要是否独立可读（问题、方法、结果、结论四要素）；关键词覆盖；引言是否交代背景、问题、相关工作、本文贡献；各节衔接有无跳跃；结论是否回应引言；参考文献格式是否统一完整。

**维度二：内容与论证质量**。核心论纲是否有充分论证支撑还是仅靠断言；命题/定理/定义的陈述是否精确、条件是否完备；有无逻辑跳跃或隐含假设；有无未经辩护的强主张（"唯一""所有""必然"）；与既有工作的关系是否清晰；开放问题与局限是否诚实对待。

**维度三：LaTeX 与数学格式**（管排版语法）。花括号是否已用 `\{` `\}` 转义（最常见的渲染崩溃原因）；set builder 竖线用 `\mid` 而非 `|`；上下限语法（`\int_0^T`）；微分元间距（`\, dx`）；Unicode 数学符号（`ℏ` 应写 `\hbar`、`∫` 应写 `\int`）；数学字体（`\mathcal`、`\mathfrak`、`\mathbb`）；括号大小 `\left` `\right`；多行公式对齐。

**维度四：语言与表达**。中英文混排中散落的英文单词是否未翻译；标点全角半角统一；病句、冗长句、歧义表达；术语一致性；口语化表达。

**维度五：引用与参考文献**。文内引用格式统一；每条含作者、标题、期刊/出版社、年份；有无该引未引；编号与正文对应；是否引用了竞争对手或批评者的工作（学术诚信标志）。

**维度六：逻辑一致性与内部自洽**。内部有无矛盾主张；命题/定理间有无循环依赖或未声明预设；数学符号全文一致；图表与正文一致；从前提能否逻辑推出结论。

**维度七：数学正确性与推导严谨性**（管公式对不对，与维度三互补）。推导步骤是否可复现（每个等式能否从前一步合法推出，有无跳步、漏项、凭空出现的项）；符号与约定是否自洽（同一 $g$、$\hbar$、$\kappa$ 全文同义，吸收常数进变量后定义是否一致）；引用标准既有结果（格点规范理论、自旋-统计定理、sine-Gordon 孤子、Bianchi 恒等式）是否前提满足、未断章取义；物理量纲一致、守恒律推导来自正确恒等式。

### 第三步：问题分级

| 级别 | 标签 | 定义 |
|:-----|:-----|:-----|
| **A级** | 严重 | 逻辑断裂、逻辑跳跃、严重矛盾、**循环论证、明显数学错误**（推导不可复现的跳步/漏项、系数与约定整体矛盾、极限退化到错误结果） |
| **B级** | 中等 | 论证不充分、术语不一致、公式渲染崩溃、重要引用缺失、结构缺失（如缺引言/结论）、**局部数学瑕疵**（符号/约定前后不一致、某一步系数漏项但不致整体结论错误） |
| **C级** | 轻微 | 标点问题、轻微语病、格式细节 |

### 第四步：输出评审报告

```markdown
## 评审报告

**论文标题**：（标题）
**评审日期**：（日期）
**总体评价**：（3-5 句：原创性、严谨性、成熟度判断）

### A级问题
| # | 位置 | 问题描述 | 建议修改 |

### B级问题
（同上表式）

### C级问题
（同上表式）

### 各维度评分
（七维各 1-10 分加简要说明；数学正确性维度须对照标准既有结果逐式核对）

### 开放问题（如需讨论）
（评审中产生的、超出论文范围但值得作者思考的问题）
```

评审报告写入 `评审报告/` 后自动 `git commit`（一篇报告一次提交），无需等待作者指示；`git push` 不自动执行，仅在作者明示"推送"时执行。报告产出后询问作者是否需要深入探讨或转为修改；在作者明确指示之前，不自行修改论文。

## 第二部分 修改

根据评审报告对论文进行系统性修改，按严重程度（A/B/C 级）逐级处理，每完成一级做一次验证，确保不引入新问题。

### 阅读报告与规划

通读评审报告，确认 A/B/C 级各有哪些问题、作者是否明确了处理范围。按「先大后小、先结构后细节」排序：结构性问题 → 逻辑问题 → 引用问题 → 格式问题（LaTeX）→ 语言问题。

### A级问题处理

每处理一个 A 级问题，**必须**在修改后立即用 Read 工具验证改后的上下文，确认替换位置正确、没有破坏周围内容，并记录修改了什么、改在哪里。

### B级问题处理

涉及文字修改的用 Edit 工具做靶向替换；涉及结构补充的在最近的自然断点处插入新段落；涉及强主张弱化的保留核心意思、添加限定词或条件说明。

### C级问题处理

C 级在完成 A/B 级后统一处理：可批量处理的（如全文字符替换）现写幂等批量替换脚本落 `_tools/` 执行（一次性，任务完即删；含中文禁止 bash 内联）；需要逐处改的用 Edit 工具。

### 第 3.5 步（可选）：去除 AI 味

作者要求或评审指出「AI 味道过重」时，在完成 A/B 级后、C 级之前专门执行一轮清洗。标志与改法全文见 `references/去AI味指南.md`（序列词滥用、套话空话、过度强调词、规整段首、连接词堆砌、句式高度一致、个性化缺失七类，含逐项对照表与保留比例）。**不删内容只改表达**，清洗后抽 3-5 段验证。

### 写后验证

每完成一级的全部修改，跑一次机器自查（脚本模板与全部技术纪律见 `references/修改技术约束.md`）：超长段落（>300 字符为 0，对照表/数据清单/代码块/引用块/列表项例外）、控制字符为 0、`$` 配对为偶、行尾符与原文一致、内链目标零未命中、交叉引用仍有效。锚点断言、反向重编号、备份清理等技术约束全在该文件，修改前必读。

命中项逐处看上下文再判断：术语引述、实际文件名、独立否定句属合法保留。另有两项机器查不出、须人工过：改后句子是否通顺；有无意外删除或覆盖原文（长文档重写时末尾段落最易丢）。

### 第 4.5 步（按需）：同步开放问题

论文含「开放问题」章节（或正文明确列出待解问题）且本次修改确认了其现状时，同步登记到 `内部草稿/开放问题总览：元相子理论待解决问题清单.md`。此项为工作区常驻写作规范，默认遵循；首次处理按 AGENTS.md「开放问题同步规范」核对登记规则（去重、来源标注、分层、改状态不删历史、不动他条），先核对总览实际结构再操作，批量增删用 Python 脚本。

### 输出修改报告

```markdown
## 修改报告
**论文标题**：（标题）
**处理范围**：A级/B级/C级/全部
### 修改清单
| # | 评审条目 | 位置 | 修改内容 | 验证方式 |
### 已知残余问题
（评审指出但作者决定暂不处理的条目及理由）
```

## 第三部分 收尾

修改报告产出后提醒作者验证修改结果。修改过程中不提交，修改完成后自动 `git commit`（一处独立修正一次提交，同一篇文档的多次编辑合并为一次），无需等待作者指示；`git push` 不自动执行，仅在作者明示"推送"时执行（完整规则见工作区 AGENTS.md「git 规范」）。

论文定稿闭环的状态登记（子理论索引徽标与日期更新）见 tianxing-academia 的「论文评审联动」节与 `protocols/评审联动协议.md`。
