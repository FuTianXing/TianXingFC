## 3. 写论文时的必守协议（完整版见 `protocols/论文写作协议.md`）

1. **公式**：所有数学公式使用 LaTeX。行内公式 `$...$`，独立公式 `$$...$$`。符号一律采用术语表标准（波核 $\mathcal{W}$、粒核 $\mathcal{P}$、相干耦合态 $\Psi$、兴衰指数 $\Xi$ 等）。
2. **文风**：用句号断句、用"然而/但/相比之下"衔接，保持学术书面语。
3. **署名与引用**：傅天行（天行新学研究院）；预印本格式"傅天行. (2026). 标题. 天行新学研究院预印本."；引用子理论优先用 ✅ 状态版本。
4. **结构**：按模板组织（摘要 → 引言 → 公理/推导 → 讨论 → 结论 → 验证材料），新论文必须明确其在体系中的理论位置（承接哪个文件、填补哪个缺口）。有数值验证的论文必配「验证材料」节：重要数值结果以「实测对期望」对照表置顶并标判据编号，随后列脚本与验证注记；只写判据编号不给读数视为数值材料未同步（2026-10-11 作者指示，常驻）。
5. **自我批判**：新推导必须按四级声明制标注严格程度（严格定理 / 条件性命题 / 定案 / 数值验证，口径见 `元相子理论已解决难题总览.md`），沿用体系内已有的批判性传统（如法向跃迁是模型假设）。
6. **开放问题同步**：论文若含"开放问题"章节，成稿/修订/评审后必须把其中开放问题同步登记到 `内部草稿/开放问题总览：元相子理论待解决问题清单.md`（去重、标来源、保留分层、改状态不删历史、不动他人条目，完整规则见工作区 AGENTS.md「开放问题同步规范」）。此项为常驻规范，默认执行，无需单独提示。
7. **提交自动，推送人工**：每完成一个实质工作单元即自动提交（粒度按主题，同一文档的多次编辑合并为一次提交）；`git push origin master` 仅在作者明示"推送"时执行。完整规则见工作区 AGENTS.md「git 规范」。此项为常驻规范，默认执行，无需单独提示。

## 4. 固化新思想进理论总纲（完整版见 `protocols/更新协议.md`）

对话中产生的新概念/新结论先写入 `内部草稿/`（注明日期、来源对话、与既有体系的关系）。🔴 **CHECKPOINT**：明确询问作者是否固化，得到确认后才按本节流程合并进对应 `理论总纲/` 文件；未经确认，`理论总纲/` 基准内容不得修改。

三条不变量：**授权在先**（"我觉得可以固化"不构成授权）；**一期一入**（同一批固化写进同一条修订记录，标注触发与来源）；**不升格**（作者裁决、可复现数值、待攻项各按自己的层级措辞，固化的只是位置）。

### 4.1 授权与预检

触发词（固化、固化进总纲、写进基准、把这批结论落到总纲、更新基准文档）触发后再动手，仅"讨论结论"不得动基准。`git status --short` 先看基准文件是否被并行会话在途修改，在途时报告中声明、锚点最小化、绝不整体重排；`rg -n '^#{1,4} '` 重读目标结构（标题层级、编号规律与待攻清单位置可能已被改写过）。

### 4.2 收料与严格程度定级

列清单：每条待固化结论 + 来源层级（作者裁决 > 定稿论文 > 验证脚本判据 > 内部草稿分析 > 他会话产物）。按四级声明制归级（严格定理、条件性命题、定案、数值验证，口径见 `元相子理论已解决难题总览.md`），固化文字的动词与级相配（判定、验证、裁决、待攻、拟议）。摘可追溯三件套：脚本路径、验证注记名、判据编号，追不回的不写。未闭合项一并带上（写明"待攻项为…"），固化位置不等于结案。

### 4.4 计数涟漪（最易漏的一步）

1. 总数一变，先全工作区扫描：`rg -n "<旧数> 项" --glob "*.md" -g "!_tools/**" -g "!外部理论参考/**"`，列全引用点。
2. 逐个同步，名称列表一起改：A 级条目常在正文里被逐一列名，只改数字会留下矛盾。
3. 同步后 `rg` 复查零残留；`外部理论参考/` 按规范不动。
4. `内部草稿/` 里的历史陈述（"当时为零条目"）仍为真，不追改成新数，加"（日期已补齐）"标注即可。

### 4.5 落笔纪律

1. 正文段落 ≤300 字符，含标点与 LaTeX 源码；拆段只插分隔符，替换前后去空白比对证明零遗漏。
2. 内链写 `[[文件名]]`；新写的引用不写书名号（既有 `《》` 按规范不强制迁移，批量转换交 wikilink-batch）。
3. 修订记录用分级列表：`  - **日期 事件名**（触发或依据）` 加缩进要点；同日多事件各占一条。
4. 同一事实只在一处展开，其余处引用；四处重复同一段会让后续同步变成四处维护。

### 4.6 落盘与检查

多处替换走 Python 脚本（写 `_tools/`，任务收尾删除）；含中文禁止 bash 内联 `-c`；锚点取无标点子串，`assert text.count(old) == 期望次数` 后才落盘；含 LaTeX 的批量替换一律 r-string 防控制字符（`$\theta$` 变 TAB + heta 是典型事故）。落盘后跑统一检查：

```
python .agents/skills/tianxing-academia/scripts/solidify_check.py <文件>... [--root D:\software\TianXingFC]
```

硬伤（退出码 1）：控制字符、wikilink 未解析。提示（不影响退出码）：超长段落、序列词套话、残余书名号。死链与条目覆盖另配 wikilink-batch 的 `scripts/link_audit.py`。

### 4.7 报告与失败分支

逐文件说明改了什么、每条结论进了哪一层、哪些属待作者确认（强度评级、规则放宽、边界判断），给出可回退提示；计数涟漪涉及的下游文件必须点名，不能只报"已同步"；末尾一句话报提交情况。失败分支：新思想与基准内容冲突 → 记入 `内部草稿/` 并说明冲突点，由作者裁决谁修正谁；待确认记录积压超过 3 条 → 主动提醒作者批量确认；作者未回应确认 → 保持暂存状态不固化。

## 5. 探索新理论方向的用法

1. **查重**：对照 `子理论索引.md`，确认新方向是否已有覆盖（徽标口径见第 2 节导航表）。已有覆盖时说明本文是深化还是修正。
2. **定位**：显式声明新理论与公理体系的关系（从公理推导 / 与既有子理论衔接 / 修正既有结论，修正须说明理由）。
3. **查符号**：对照 `术语表.md` 检查术语冲突；引入新符号时先写入 `内部草稿/术语提案.md` 待确认。
4. **存放**：探索草稿放 `内部草稿/`，定稿论文放工作区根目录，完成后登记到 `子理论索引.md`。
5. 失败分支：若新方向与既有子理论结论冲突且无法裁决 → 记入 `内部草稿/` 并列出冲突清单，提交作者裁决，不强行推进。

## 6. 论文评审联动（完整版见 `protocols/评审联动协议.md`）

1. 调用 `paper-review` 评审（七维 + 体系专属附加检查 E1-E7），产出 A/B/C 分级报告。
2. 展示报告并确认处理范围后，在 paper-review 的修改流程中按 A → B → C 逐级修改，每级验证。
3. 复核后更新 `子理论索引.md` 状态：已入分组清单的论文改清单行徽标与日期，未入组的改状态跟踪区（评审中 → 已定稿 / 修订中）。
4. 失败分支：paper-review 不可用 → E1-E7 人工评审回退；评审结论与体系基准冲突 → 记入 `内部草稿/` 由作者裁决。

## 7. 不要做（反例黑名单）

- 不要夸大严格程度：按四级声明制标注（严格定理、条件性命题、定案、数值验证）。
- 不要重复推导既有结论：子理论索引中 ✅ 状态的内容直接引用。
- 不要未经确认修改 `理论总纲/` 基准内容，也不要用未确认的新符号或被取代的初版做引用依据。
- 不要回避与既有子理论的冲突：记入 `内部草稿/` 提交作者裁决。
- 不要擅自推送：`git push` 仅在作者明示"推送"时执行。
