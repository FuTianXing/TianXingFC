# 更新协议：混合模式（对话中暂存 + 作者确认后固化）

> 本技能是活的知识库。更新遵循"暂存 → 确认 → 固化"三步流程，未经作者确认，`D:/software/TianXingFC/理论总纲/` 基准内容不得修改。

## 1. 核心原则

- `D:/software/TianXingFC/理论总纲/` 是**基准知识库**：内容经过作者确认，是写作与一致性检查的依据。
- `drafts/` 是**暂存区**：对话中产生的新思想、新概念、新结论，先写入这里。
- 只有作者明确说"确认/固化/记入体系"时，才把 `drafts/` 内容合并进 `D:/software/TianXingFC/理论总纲/`。
- 每一步更新都要可追溯：注明日期、来源（哪次对话/哪篇论文）、与既有体系的关系。

## 2. 暂存规则（对话中触发）

以下情况发生时，在 `drafts/` 新建或追加记录：

1. 对话中出现新的理论概念、新符号、新公式推导。
2. 对话中修正或质疑了既有结论（记录修正理由，不直接改 `D:/software/TianXingFC/理论总纲/`）。
3. 对话中提出新的理论方向或研究计划。
4. 新的论文成稿（定稿论文放工作区根目录，同时在 `drafts/` 或索引中登记）。

**暂存文件命名**：
- 新概念/新推导：`drafts/新概念-<主题>.md`
- 术语提案：`drafts/术语提案.md`（追加式，一条一条列）
- 新方向/研究计划：`drafts/研究方向-<主题>.md`

**暂存记录格式**：

```markdown
# <主题>

- 日期：YYYY-MM-DD
- 来源：对话/论文 <标识>
- 状态：待确认 | 已确认 | 已固化 | 已废弃

## 内容
（新思想/公式/概念，LaTeX 规范）

## 与既有体系的关系
（承接哪个公理/定理/子理论；是否与术语表冲突；若引入新符号列出提案）
```

## 3. 确认流程（作者触发）

1. 作者说"确认""固化""记入体系"（或类似表述）后，将暂存内容并入 `D:/software/TianXingFC/理论总纲/`：
   - 属于已有主题 → 合并进对应文件（`公理体系.md` / `天行方程与DOGA.md` / `元相子理论.md` / `术语表.md`），在文件头更新来源与日期。
   - 全新主题 → 新建知识文件，并在 `子理论索引.md` 登记。
2. 合并后更新 `drafts/` 中对应记录的状态为"已固化"。
3. 涉及符号或术语变更时，同步更新 `术语表.md` 与涉及论文的引用规范。

## 4. 修订既有结论的流程

1. 新论证若与 `D:/software/TianXingFC/理论总纲/` 中既有结论冲突，先在 `drafts/` 记录新论证与冲突点。
2. 向作者说明：谁修正谁、依据是什么、影响哪些下游子理论。
3. 作者确认后，修改 `D:/software/TianXingFC/理论总纲/` 对应文件，并在文件头保留修订记录（旧结论去向、修订日期）。

## 5. 撤销与废弃

- `drafts/` 中废弃的暂存记录标记"已废弃"，不删除（保留思考轨迹）。
- 错误的 `D:/software/TianXingFC/理论总纲/` 内容：经作者确认后修正，并在文件头记录勘误。

## 6. 技能自身的维护

- 技能结构或协议需要调整时（如新增协议文件），同样先经作者确认。
- `SKILL.md` 的知识库导航变化时同步更新。
