# 作废轮次归档（Archive Void Rounds）

工作区：天行新学（`D:\software\TianXingFC`）。验证材料在 `验证脚本/`，归档在 `归档/`。本技能只管「作废材料的退出路径」，不判定物理，也不改任何读数。

## 0 三条不变量

**其一，作废不是「结论被否」。** 一个轮次被判否、被判负、某条判据 FAIL，都不构成归档理由，这些都是有效产出。归档的唯一理由是：该轮的读数整体取在一个后来查实的无效构型或无效实现上，**且该轮不以独立的实现发现或协议发现为产出**。

**其二，识别在先、移动在后。** 先出候选清单与逐轮判据，全部核对完再动文件。分类错误两个方向都不可逆：把有效证据线归档会让索引失效，把作废轮留下会让下轮继续引用死读数。

**其三，归档是移动不是删除。** 一律 `git mv` 或 `mv`，保 `git log --follow` 历史。`归档/` 下只读保存，原件正文不改。`验证脚本/README.md` 的原条目保留，行末追加归档位置与作废范围。

## 1 不能按关键词判作废

全库 grep「撤回|作废|判否|失效|不成立」，在 `验证脚本/README.md` 上会命中约 110 行，其中绝大多数是「某一判据判否」而非「整轮作废」。按关键词批量归档必然误伤。

正确做法是**扫结构指纹，不扫关键词**。先从根因轮的注记里抄出缺陷的**准确形态**，再据此构造指纹。

以 2026-10-24 洛伦兹线为例：第 809 号查实第 691 号起的 boost 初值构型误设——文档字符串声明「包络 $\psi(\gamma x)$、相位梯度 $-\omega_b \gamma v x$、外场不被变换」，代码实写 `s0 = shrink*xf`、`th0 = -wb*shrink*v*xf`、`sg = sigma*shrink`，调用处一律传 `shrink = 1.0/g`。指纹因此是「装置含 `shrink` 收缩构造」，而不是「注记里写了不成立」。

## 2 识别四步

1. **定位根因轮**。哪一轮先把缺陷说出来，抄它的「声明 / 实写 / 后果」三处对照。这是后续所有判据的尺子。
2. **指纹扫候选**。`grep -l "<缺陷签名>" 验证脚本/*.py` 得脚本候选集，再逐个核。
3. **分「唯一构型」与「被比较的构型」**。这一步最易错。第 695、696 号也含 `shrink`，但它们的 `make_ic` 是显式双样式（`style='g692'` 传 `sh = 1/gg`、`style='boost'` 传 `g`），两种样式都是**被比较的对象**，不是唯一取样方式，故不归档。判据：看该构型是否被参数开关控制、是否成对出现。
4. **分「整轮作废」与「单判据作废」**。状态行只写「某判据判否」而其余节仍有效者不归档（第 749 号 D2 判否，第五节仍有效）。「提出—撤回」成对结构不拆对（第 699 号判语由第 700 号撤回、第 774 号核心结论由第 778 号替代，撤回方本身是有效读数）。

## 3 三类必须保留的反向项

归档前逐类过一遍，命中即留下并写明理由：

| 类型 | 实例 | 留下的理由 |
| --- | --- | --- |
| 实现或协议发现 | 第 789 号查出 `eigsh(L, k=1, which='SA')` 未固定 `v0`，起始向量随机致跨协议散布 | 被测算符不含误设构型，发现与构型无关 |
| 读数方法稳定性度量 | 第 797 号 BA3 滑动平均跨三窗长散布 $0.0000$ 至 $0.0014$ | 度量对象是读法而非物理量 |
| 几何或幂律事实 | 第 800 号 CA2 半高宽除以 $vT$ 跨档比值 $1.0000$、$1.0042$、$0.9969$、$1.0042$ | 尾长等于碎屑能跑过的距离，与构型无关 |

另有一类是**装置不含该构型的独立证据线**，同样保留。洛伦兹线里第 695 至 714 号、752、768、771、775 号的 `grep shrink` 计数全为 0，产出 $c_0$ 与 $c_1$ 的身份判定与 dev 形式，不动。

## 4 归档目录与 README

目录名按「主题加轮次」：`归档/洛伦兹线误设构型轮次/`、`归档/实现缺陷波及轮次/`。同一时段的两次撤回各自独立建目，README 里写明「勿混为一事」。

README 七节，照 `归档/洛伦兹线误设构型轮次/README.md`：

1. 标题 `# <主题>（归档）`
2. 归档日期、归档依据、处置方式三段，用行内加粗标签，不分节
3. `## 缺陷的确切内容`：声明 / 实写 / 后果三列表
4. `## 为什么另有一套装置`（有替代轮时写）
5. `## 本目录收录的轮次`：轮号 / 脚本 / 注记 / 处置四列表
6. `## 未归档的相关轮次`：逐条写留下的理由
7. `## 权威结论`：指回替代轮

**处置方式必须与事实逐条对上。** 首版写「内容未改一字」与实际不符，归档过程改了 16 处 wikilink 前缀与 5 处图片路径，须改准为「正文未改一字，改动只有两处路径适配」并逐项列出。

## 5 执行六步

1. 建目录、写 README。
2. `git mv` 脚本，同目录改名 git 记 R100 全等。
3. `mv` 注记，来源是 `验证脚本/` 与 `内部草稿/` 两处。
4. 修 wikilink 前缀：全库遍历 `**/*.md`，把 `[[验证脚本/<归档件>` 与 `[[内部草稿/<归档件>` 改为 `[[归档/<主题>轮次/<归档件>`。
5. **修图片相对路径**：归档目录比 `验证脚本/` 与 `内部草稿/` 深一层，`](../images/` 须改 `](../../images/`。先例目录的注记用反引号记图路径（`` `images/xxx.png` ``）从未被渲染，故没暴露这个坑；用真嵌入 `![]()` 的必须改。
6. README 对应行末追加标注，格式 `。**已归档**：脚本与注记移入 \`<目录>/\` 只读保存，<作废范围>，依据见 [[<替代轮注记>]]`。作废范围逐行定制，不要一律写「本行作废」。

## 6 四段核验

每段都要跑，任一段不为零即回查：

| 段 | 查什么 | 期望 |
| --- | --- | --- |
| A | 全库是否还有链接指向旧路径 | 0 |
| B | 归档目录内每个 md 的 wikilink 与 `![]()` 出链 | 全部解析 |
| C | 全库指向归档目录的 wikilink 目标 | 全部存在 |
| D | 原路径的删除是否都已进暂存区 | 无遗留 `D` |

脚本直接用：

```
python .agents/skills/tianxing-archive/scripts/archive_audit.py --archive 归档/<主题>轮次 --old 验证脚本 --old 内部草稿
```

A 段的 `moved` 名单默认取归档目录内**除 README 外**的 md。归档目录的 README 是归档时新建的说明文件，从未在 `验证脚本/` 下存在过，把它算进名单会把全库所有 `[[验证脚本/README]]` 误报成残留（首次实测误报 99 条）。必要时用 `--moved <名字>` 给显式名单。

**顺手也扫一遍既有归档目录。** 2026-10-24 扫 `归档/实现缺陷波及轮次/` 得 140 处真断链：A 段 99 条是库内其它文档仍指向 `验证脚本/` 下那 12 轮的旧路径，B 段 41 条是该目录内部互引未改前缀。先例归档时**没有做第 5 节第 4 步的 wikilink 前缀适配**，只留了 README 说明，故这些链接全部悬空。新归档不得重复这个疏漏。当日已补 129 处（`1084418`），涉及 41 个文件。

**B 段的 `[[理论总纲/]]` 属库内惯例，不是断链。** 全库 65 个文件都这样写，用于把「基准目录」当名词提及（如「`[[理论总纲/]]` 基准文档未经作者确认不改动」）。除非该行确实在指某个具体文档，否则不改，也不要计入归档账。

## 7 踩坑清单

1. 关键词扫描不判作废，见第 1 节。
2. 双样式构型不等于误设构型，见第 695、696 号。
3. 提出—撤回成对结构不拆对，见第 699、700 号与第 774、778 号。
4. 图片相对路径少退一级，造成 5 处断链。
5. 追加标注时先加句号会造出「。。」，替换前先用 `count` 核。
6. `git add` 只加新路径会漏原路径的 `D`，须用 `git status --porcelain` 筛 `st in ('D',' D')` 逐条 `git add -A -- <path>`。
7. 死链审计的目录范围要排除 agent 记忆目录（`.trae/`、`.workbuddy/`、`.workbuddy-ai/`、`.zcode/`、`.claude/`），否则会报一堆与工作区无关的 `file:///` 死链。
8. 归档目录名逐字核对，「误设」不是「误区」。
9. 全库死链检查的基线本就有数百条历史遗留（模板占位 `[[文件名]]` 之类），不要把这批算进本轮账。只查被移动目标与实际引用方。
10. **wikilink 前缀适配不能省**。先例目录漏了这一步，留下 140 处断链，事后再补代价更高。
