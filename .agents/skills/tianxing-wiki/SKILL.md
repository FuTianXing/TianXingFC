# tianxing-wiki 新建与维护 wiki 词条

## 0. 授权与预检

1. 触发词：写词条、建词条、wiki 词条、名词解释、名词条目、补词条、更新词条、给某概念写一篇解释。触发后再动手。
2. 先去重：`wiki/README.md` 的「现有词条」表逐行核对（含近义词），已存在则改走维护流程；`rg --files wiki` 复核文件名。
3. `git status --short -- wiki` 看是否被并行会话改动；在途时在报告里声明。
4. 重读 `wiki/README.md` 的通用模板与写作要求：模板可能已随体系演进改过，勿凭记忆写。

## 1. 收料与定级

1. 列清单：该名词在体系内的定义、机制与读数，各标来源（论文 / 验证注记 / 裁决 / 术语表 / 速览）。优先级：作者裁决 > 定稿论文 > 验证脚本判据 > 内部草稿。
2. 定三项元数据，都要可核实：**分类**（物理概念 / 几何结构 / 机制 / 判据 / 术语 / 定理）、**定案状态**（已确认 / 数值确认 / 方案定案 / 纲领性，未定案者照实写）、**首次出现**（用 `git log -S "<词>" --oneline | tail` 找最早文档，或标已知定名文档）。
3. 摘可追溯三件套：脚本与条目号、验证注记名、判据编号。定义与机制里的每个数字都要能追回来源，追不回的不写。
4. 一个名词多义时先消歧（照 [[绕数]] 把两类绕数分开的做法），把各类的适用域写清。

## 2. 词条结构（八节模板）

```markdown
# <名词>

**<名词>**是<一句话定义>。（加粗术语开头，定义必须独立可读：不依赖本词条之外的概念解释）

| 元数据 | |
|---|---|
| 分类 | <类别> |
| 定案状态 | <状态 + 依据> |
| 首次出现 | <最早引入文档> |
| 相关词条 | <[[词条名]]，顿号分隔> |

## 概述
## 定义
## 机制
## 通俗类比
## 例子
## 与其他概念的关系
## 参见
## 参考资料
```

八节按序保留，按需增减；定义涉及公式时用行内 `$...$` 或独立 `$$...$$`；类比放在机制之后，各写一句说明与局限；例子用表格，每行给「成立 / 不成立」与原因；参见列 wikilink（未建立者写纯文本加「（待建）」）；参考资料格式为 `<文档名>（<位置>，<日期>）`。

## 3. 落笔纪律

1. 写作铁律全查：禁序列词与套话。
2. 正文段落 ≤300 字符（表格、公式块、列表项不计）；超出者按语义边界拆分。
3. 引号：语料惯例用 ASCII 双引号（2026-09-19 实测 39 条词条中 37 条如此），检查器只作提示不判硬伤；风险在落盘环节：经 JS 字符串写入时 ASCII 双引号会提前闭合字符串造成截断，故落盘走 node_repl 的 String.raw 模板串，或改用中文引号。
4. 未定案不得写成定案：状态栏与正文口径一致，纲领性内容写「纲领性」并在正文注明未闭合项。
5. 与既有词条互链：同一事实只在一处展开，其余处用 [[链接]] 指过去。
6. wiki 只做通俗解释，不改任何基准文档；定案口径以论文、`理论总纲/术语表.md` 与 `理论总纲` 其他基准为准。

## 4. 落盘与检查

1. 落盘：`wiki/<名词>.md`（命名取名词本身）。含 LaTeX 时用 `node_repl` 的 `fs.writeFileSync` 写，勿走命令行通道；分段落写入并逐段复检长度。
2. 索引：在 `wiki/README.md` 的「现有词条」表补一行（词条链接 / 定义首句摘要 / 分类 / 定案状态），插入到同主题词条附近。
3. 检查：

```
python .agents/skills/tianxing-wiki/scripts/wiki_check.py wiki/<名词>.md
```

硬伤（退出码 1）：缺一级标题、定义首句未加粗、元数据表缺字段、缺必需小节、控制字符。提示：超长段落、ASCII 双引号、缺可选小节、残余书名号。元数据字段与定义首句的判据容忍对齐填充与括注（**名词**（原文）是…）。2026-09-19 全量实跑：39 条词条 37 条通过，余 2 处历史违规已修，现语料全绿。

4. 内链可解析性另配 `wikilink-batch` 的 `scripts/link_audit.py`。

## 5. 计数与分工

1. 词条数为 README 表格的行数；若其他文档引用该数字，一并同步。
2. 三层分工：`wiki/` 通俗解释（可独立阅读、带类比）；`理论总纲/术语表.md` 一句话定义（服务于快速查阅）；`理论总纲/天行新学核心洞见速览.md` 洞见条目（只追加从句）。同一名词三层并存，口径必须一致。
3. 固化新读数进基准时走 `tianxing-solidify`，词条只在其后同步口径。

## 6. 报告

1. 逐条说明：新增或修订了哪个词条、定义首句、元数据三项取值与依据、检查结果。
2. 列出待作者确认项（多为定案状态定级与一处消歧取舍）。
3. 末尾一句话报提交情况（已提交 N 个文件；未获作者明示推送时注明「未推送」）。

## 特例速查

- 与既有词条近义：先判是否同一概念。同一概念合并进既有词条并在报告里说明；不同概念各自立条并互相参见。
- 名词有多个读法：照 [[绕数]] 的做法在概述里先分开，再逐节写清适用域。
- 只译不造：外来词取通行译名，首见处给原文；不新造术语。
- 修订既有词条：改动超过一句时在文末「参考资料」下加一行修订说明（日期 + 改动点），不改他人未确认的定级。
