## 1 错误的形状

第 692 号的物理档预算写作 $B_{\rm phys} = (m_e/m_P)^2/12$。体系里 $m_P$ 指普朗克质量，第 622 号恒等式 $\xi = m_P/m_e = 2.3892\times10^{22}$ 正是据此而来。然而脚本第 205 行写的是

```python
MR2 = (1.0 / 1836.15) ** 2
B_phys = MR2 / 12.0
```

$1836.15$ 是质子与电子的质量比 $m_p/m_e$，因此这一行算的是 $(m_e/m_p)^2/12$，而注释与注记都标成 $(m_e/m_P)^2/12$。一字之差（$p$ 与 $P$），两个质量相差二十二个数量级。

## 2 判据与读数

| 量 | 数值 |

| 脚本实算 $(m_e/m_p)^2/12$ | $2.47173803\times10^{-8}$ |
| 两者之比 | $1.69315\times10^{38}$ |

判 E1 通过（错误确证），并给出错误倍率 $1.69\times10^{38}$。

**E2 内部一致性核对。** 同一注记的 §1 写道「物理档宽度 $\xi = m_P/m_e = 2.389\times10^{22}$ 格」，与预算里的 $m_e/m_P$ 互为倒数；若预算真用 $m_e/m_P$，则应有 $(m_e/m_P)^2 = 1/\xi^2 = 1.752\times10^{-45}$，与注记自报的 $2.97\times10^{-7}$ 不符。注记自身前后矛盾，判 E2 通过（独立于 E1 的第二条证据链）。

## 6 教训

**其一，常数替换错误在下游成批继承。** $m_p$（质子）与 $m_P$（普朗克）只差一个字母大小写，而两者相差二十二个数量级。这类错误一旦进入脚本，注记、通俗版、总览、主论文、索引、README 会逐层抄录同一数字，且各层互不校验，错误因此可以穿过六道工序存活。防线只能设在脚本层：显式常量名加注释，并在注记中同时写出该比值的量级（$10^{-23}$ 与 $10^{-4}$ 一眼可分，若初版注记写的是 $4.19\times10^{-23}$ 而非 $2.97\times10^{-7}$，错误当场就会暴露）。

**其二，判语方向不变不意味着错误无害。** BC5 初版判 CHECK、更正后仍判 CHECK，若只看判语会以为无事。但缺口的量级从四个数量级变成四十二个，这直接改变了后续路线选择的理由：初版读起来像「再努一把或许能补上」，更正后是「差四十二个数量级，任何模拟外推都不可能触及」。第 693 号终止宽档路线的判决因此比原文更硬，比原文所说的更难绕过。

**其三，交叉核对要挑互相独立的量。** 本轮抓到错误靠的是 E1（与 CODATA 常数对表）与 E2（与本注记自报的 $\xi$ 对表）两条互不依赖的证据。E2 尤其廉价：同一文档内 $\xi = m_P/m_e$ 与预算 $(m_e/m_P)^2/12$ 必须互为倒数关系，写成两处即可自检。
