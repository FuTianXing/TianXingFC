## 一、三条容量的表达式

其一，摆程容量。一次摆程相位扫过 $2\pi$（满周闭合），读数在凝固时刻取得一次，故每摆程的登记位为一：

$$C_{\text{摆程}} = n_{\text{摆程}}\ \text{bit}\qquad(\text{即“一次摆程一次记录”}).$$

其二，标签容量。锁定模的扇区标签有 $N_W = L$ 个取值（命题 17），标签空间的香农容量为

$$C_{\text{标签}} = \log_2 N_W = \log_2 L\ \text{bit}.$$

其三，记录容量。跨层记录不可逆、写入次数守恒，协议窗口内的可写次数以摆程数封顶：

$$C_{\text{记录}} = n_{\text{摆程}}\ \text{bit}.$$

三条表达式的右侧只含框架量（摆程数、$n_{\text{摆程}}$、扇区数 $N_W = L$），不含 $2\sqrt2$、$\cos^2(\pi/8)$ 或 $\varepsilon$。

## 二、R1 与 R2 检查

R1（只含框架量）：通过。三条都写成摆程数、扇区数、记录数的函数；目标值未出现在任何表达式中，也无处可反推。

R2（独立立起）：通过。三条的输入分别为[[元相子几何动力学——束缚振荡修订整合版]]的摆程闭合、[[锁定帧与格距无关性：先验纠缠的定量形式化]]的命题 17、以及测量线的跨层记录口径；推导链不引用方向三的任何结果。

两点如实标注。其一，R1 与 R2 是"防重述、防特设"的形式判据，通过它们只说明表达式干净，不说明容量原理已经成立。其二，三条表达式目前都还是"登记位计数"，尚未与任何界勾连；勾连在 R3 与 R4。

## 三、R6 首版：容量为什么取记录单位

主线的候选是标签容量，但 $\log_2 L$ 的标签容量进不了消息。原因是标签的**身位**：

- 标签由制备给定（联合分支锁定，命题 25 的离散部分），两侧共享，Alice 在协议中不可改写。它是**共享随机性**，已经免费在协议里（协议的公共随机源），但不是通道。
- 消息必须由 Alice 写入，而框架允许的写入原语只有跨层记录（不可逆、次数守恒）。于是消息容量的单位是一次记录，$m$ 比特消息即 $m$ 次记录。
- 由此 $\log_2 L$ 的标签容量不构成"额外可用容量"，它只是共享随机性预算的一部分；消息容量由记录侧给出，恰为每记录一比特。

这一步给出的是容量的**身份**（消息等于记录），不是 $\cos^2(\pi/8)$ 的推导：后者仍待 R3 与 R4。须防的两种失败形态照判据草案：若把容量写成希尔伯特空间维数的函数，是重述；若容量上界为凑目标值反推，是特设。

## 四、与信息因果性的接口形式

信息因果性不等式为 $\sum_k I(a_k : G_k) \le m$。框架版把右侧读作记录数：

$\sum_k I(a_k : G_k) \le m, \qquad m = n_{\text{记录}}\ (\text{记录数}).$

R3 的形式对照（文档级；数值证据只有古典锚点一条）：

| 框架侧量 | 标准侧量 | 对应 |
| --- | --- | --- |
| 消息计量：一次记录 | 经典比特数 $m$ | 一次记录 = 一比特消息 |
| 提取量 $\sum_k I(a_k : G_k)$ | 同一量 | 定义相同 |
| 预算不等式 $\sum_k I \le m$ | $\sum_k I_k \le m$ | 形状相同 |
| 无资源时 $J = m$（古典锚点） | 经典情形取满 | 数值证据（R3 判据） |
| 退化条件：一次记录即一比特消息 | 标准极限 | 由容量身份给出 |

文献原文的逐条核对仍归论文开放问题一。如实标注：这一步只把外部原则的**输入端**换成框架量，原则本身的地位仍为引用级，本稿不主张其地位变化。
